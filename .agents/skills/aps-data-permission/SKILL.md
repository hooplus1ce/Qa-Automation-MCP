# APS 数据权限端到端自动化测试 Skill (APS-Data-Permission-E2E)

## 1. 触发场景
当执行 APS / SCM 系统的权限管理相关测试任务，且满足以下任一条件时强制启用本规范：
- 一级/二级功能分类涉及「数据权限 / 角色权限 / 功能权限 / 数据范围表」；
- 用例包含「数据范围表 / 范围表过滤 / 字段级规则校验 / 组织隔离 / 部门隔离」；
- 需要多角色联动验证数据可见性、越权防护边界与字段级过滤生效情况。

---

## 2. APS 权限架构设计与业务逻辑流

APS 系统采用典型的 **RBAC（基于角色的访问控制）+ ABAC（基于属性的细粒度访问控制）融合模型**，分为三个核心层级：

```mermaid
graph TD
    A[APS 权限管理体系] --> B[1. 功能权限 (RBAC 粗粒度)]
    A --> C[2. 数据权限 (RBAC 组织级)]
    A --> D[3. 数据范围表 (ABAC 字段级)]

    B --> B1[菜单路由与模块可见性]
    B --> B2[按钮与操作权限: 列表查询 / 导出 / 查看 / 日志等]

    C --> C1[全部数据]
    C --> C2[本部门数据]
    C --> C3[本部门及以下数据]
    C --> C4[仅本人数据]
    C --> C5[自定义配置: 勾选特定组织架构/部门树]

    D --> D1[适用对象: 业务模块如 APS销售订单/产线管理]
    D --> D2[数据字段: 订单号/使用组织/物料编码等]
    D --> D3[校验规则: 包含 / 等于 / 不等于等]
    D --> D4[条件值 + 逻辑连接词: 并且 / 或者]

    D --> E[角色绑定: 角色管理 -> 模块 -> 列表查询 -> 权限范围列]
    E --> F[用户分配: 用户管理 -> 分配角色]
    F --> G[数据网关拦截: 接口 pageQuery 注入 SQL 动态过滤]
```

### 三层权限差异对照

| 权限维度 | 控制层级 | 配置入口 | 典型表现 / 生效方式 |
| :--- | :--- | :--- | :--- |
| **1. 功能权限** | 菜单与按钮 | 角色管理 > 配置功能权限（弹窗） | 控制页面左侧导航树中模块是否可见，以及页面内操作按钮（如新增/导出）是否渲染。 |
| **2. 数据权限** | 组织与部门 | 角色管理 > 配置数据权限（弹窗） | 5种枚举：`全部数据`、`本部门数据`、`本部门及以下数据`、`仅本人数据`、`自定义配置`（勾选部门树）。按账号所属组织/部门进行粗粒度隔离。 |
| **3. 数据范围表** | 数据字段属性 | 系统管理 > 数据范围表 + 角色详情 > 权限范围 | **最小颗粒度控制**。为列表查询（`pageQuery`）注入动态校验规则（如 `销售订单号 包含 JK`），仅放行满足条件的数据行。 |

## 3. 账号与运行环境隔离契约

测试必须保证「配置端」与「受控验证端」彻底隔离：

1. **方案 A：物理双浏览器接管模式（实操调试首选）**：
   - **Port 9223 (超级管理员端)**：账号 `胡嘉斌`（或 `admin`），负责数据范围表创建、角色绑定与用户角色授权；
   - **Port 9222 (受控验证端)**：账号 `权限测试`（账号 `Hooplus1cer`），仅分配受测角色，负责核验列表过滤与越权拦截；
   - 分别通过 `browser_connect(address="127.0.0.1:9223")` 与 `browser_connect(address="127.0.0.1:9222")` 登记并管理。
2. **方案 B：单浏览器多账号独立上下文（无外部调试端口时推荐）**：
   - **管理员上下文**：调用 `profile_open(profile="aps")` 打开管理员会话；
   - **测试账号上下文**：调用 `profile_open(profile="aps_approver")` 开启独立 BrowserContext（Cookies 与 LocalStorage 隔离）；
   - 测试完毕调用 `profile_close` 成对关闭。

## 4. 标准端到端测试链路 (5 大阶段 SOP)

### 阶段 1：数据范围表配置（管理员端）
1. 管理员端直达模块：调用 `nav_menu(menu_name="数据范围表", tab_id=admin_tab)`；
2. 点击新建：调用 `click(target="text:新 增", tab_id=admin_tab)` 进入编辑数据范围表页面；
3. **基础信息填写**：
   - 范围表名称：输入唯一业务名称（如 `销售订单-包含JK范围表`）；
   - 适用对象：下拉选择对应业务场景（如 `APS销售订单`）；
4. **VTable 明细规则配置（关键实操交互）**：
   - 点击 `[新 增]` 增加规则行；
   - **数据字段**：双击单元格或点击进入编辑态，输入/选择目标字段（如 `销售订单号`），按 `ENTER` 提交；
   - **校验规则**：双击单元格输入校验规则（如 `包含` / `等于`），按 `ENTER` 提交；
   - **条件值**：双击单元格输入具体过滤值（如 `JK`），按 `ENTER` 提交；
   - **条件**：多条规则时配置逻辑连接词（`并且` / `或者`）；
5. 保存与断言：点击页面顶部 `[保 存]` 按钮，调用 `wait_message(pattern="新增成功|成功")` 确认入库，记录生成的范围表编码（如 `FW00020`）。

---

### 阶段 2：角色权限与数据范围绑定（管理员端）

> ⚠️ **高危避坑警告**：严禁点击角色管理列表上方的 `[配置数据权限]` 按钮！该按钮仅用于粗粒度组织架构树配置，无法绑定数据范围表。

1. 调用 `nav_menu(menu_name="角色管理", tab_id=admin_tab)` 直达列表；
2. **角色创建/选择（推荐新建隔离角色，见避坑指南 5.1）**：
   - 点击 `[新 增]` 进入 `roleManagementAdd?mode=create` 页面；
   - 填写 `角色名称`（如 `销售订单-JK范围测试`）与 `角色编码`（如 `SO_JK_TEST`）；
3. **功能模块与操作定位**：
   - 在左侧功能权限树中，展开目标模块路径（如 `销售预测管理` > 选中 `销售订单`）；
   - 右侧 VTable 呈现该模块的操作权限列表（`列表查询`、`导出`、`查看`、`日志` 等）；
4. **权限开通与范围绑定**：
   - 点击 `列表查询` 行的 `有权` 单元格（`col: 2`），确保设置为 `true`；
   - 双击该行的 **`权限范围`** 列单元格（`col: 4`）；
   - 向弹出的编辑输入框中输入步骤 1 中创建的范围表名称（如 `销售订单-包含JK范围表`），按 `ENTER` 键提交；
5. 保存角色：
   - 点击页面顶部 `[保 存]` 按钮；
   - 抓包/通知断言：监听 `sys/role/createRole` 或 `sys/role/updateRole`，确认接口返回 `ok: true` 且 `buttonDataScopeList` 中包含 `{ buttonCode: "aps:apsSaleOrder:pageQuery", dataScopeId: ... }`。

---

### 阶段 3：用户角色授权分配（管理员端）
1. 调用 `nav_menu(menu_name="用户管理", tab_id=admin_tab)` 进入用户管理；
2. 在用户列表 VTable 中，定位受控测试账号（如 `权限测试` / `Hooplus1cer`）；
3. **勾选复选框**：点击对应行首的复选框单元格（`col: 0`），确保该行被选中（行背景变深/checked 为 true）；
4. 点击顶部工具栏的 `[分配角色]` 按钮；
5. 在弹出的 AntD 弹窗中，通过 `antd_select` 选中步骤 2 创建的角色（如 `销售订单-JK范围测试`）；
6. 点击弹窗 `[确 定]` 按钮，并断言用户列表中的 `当前角色` 列更新为目标角色。

---

### 阶段 4：受控账号实机隔离验证（验证端）
1. 切换至测试账号会话（`tab_id=test_tab`）；
2. 刷新页面或调用 `refresh(ignore_cache=True)`，确保最新的角色与权限配置生效；
3. 调用 `nav_menu` 导航至受测业务模块（如 `销售订单`，面包屑确认到达 `销售预测管理 > 销售订单`）；
4. 点击 `[查 询]` 按钮触发数据检索；
5. **三重严格断言（基于结构化探针，禁止盲目截图断言）**：
   - **① 数据总量差分断言**：对比配置前后的 `rowCount`，确认总记录数按预期缩减；
   - **② 字段值 100% 规则合规断言**：调用 `vtable_inspect(col=目标字段列)` 提取全量可见单元格文本，断言所有数据行均严格满足校验规则（例如：所有销售订单号均包含 `JK`）；
   - **③ 越权数据 100% 拦截断言**：显式断言配置前存在且不符合规则的数据（如 `SO20260921001`）已彻底被过滤剔除，绝不可见。

---

### 阶段 5：证据留痕与环境清理
1. 调用 `vtable_inspect` 保存最终验证成功的表格数据切片；
2. 调用 `screenshot(path=".dpmcp/verify/permission_rule_verified.png")` 留痕视觉验收凭证；
3. 恢复账号原角色或保留用于持续自动化回归。

## 5. 实战避坑与故障排查指南 (Battle-Tested)

### 5.1 存量角色保存报错：`按钮“xxx”不属于当前角色可配置菜单`
- **根因**：存量角色（如 `权限测试专用`）可能在历史版本中被赋予了某些已被废弃、迁移或不可配置的按钮权限（如 `spo:barCodeReprint:print`）。在角色详情页点 `[保 存]` 时，前端会提交全量历史 `buttonIds`，导致后端校验拦截失败。
- **标准解法**：**不要尝试在存量脏角色上强行覆盖修改**。直接在 `角色管理` 点击 `[新 增]` 创建一个全新的纯净角色（如 `XXX-范围测试`），全新角色仅包含目标模块的 `列表查询` 及绑定的数据范围表，保存 100% 成功；随后在 `用户管理` 中将该新角色分配给测试账号即可。

### 5.2 VTable 单元格选择 vs 复选框勾选（Checkbox 门槛）
- **现象**：点击了某行单元格，再去点击 `[编 辑]` 或 `[分配角色]` 时，页面提示「请选择一条记录进行编辑/操作」。
- **根因**：VTable 的单元格选中（Cell Focus，点击文本或空白）与行复选框勾选（Row Checkbox，`col: 0`）是独立状态。顶部工具栏按钮只识别 `col: 0` 复选框状态。
- **解法**：调用 `vtable_click_cell(col=0, row=target_row)` 显式点击行首复选框后再触发操作按钮。

### 5.3 多标签页与多 iframe 激活态判定（多模块并发陷阱）
- **现象**：调用 `click` 或 `find_elements` 时找不到按钮，或者操作作用在了错误的页面上。
- **根因**：APS 系统主框架为单页多 Tab 模式（`.ant-tabs-tab`），每个打开过的模块都保留在一个隐藏的 iframe 中。切换标签或关闭标签时，活跃 iframe 会发生变动。
- **解法**：
  1. 切换模块优先调用 `nav_menu`，其内部已包含复用标签与等待目标 iframe 激活逻辑；
  2. 多模块操作前，调用 `frame_list` 检查当前 `displayed: true` 的 iframe 是否为目标页面；
  3. 复杂表单完成后，可主动关闭多余标签页（点击对应 tab 的 `.anticon-close`）。

### 5.4 VTable 单元格内联编辑机制
- **交互规范**：VTable 是基于 HTML5 Canvas 绘制的高性能表格，单元格编辑时会动态挂载一个绝对定位的 `<input>` 浮层（类名含 `table-focus-control` 或内联样式 `position: absolute`）。
- **稳定输入姿势**：
  1. 调用 `vtable_click_cell(col=..., row=..., double_click=True)` 唤起内联输入框；
  2. 定位生成的可见输入框并调用 `element_input(element_id=..., text=...)` 写入内容；
  3. 必须调用 `press_key(key="ENTER")` 触发提交，否则离开单元格后数据会丢失。

### 5.5 同名业务模块与适用对象映射
- **现象**：系统内可能存在同名菜单（如 `销售管理 > 销售订单` 是老版 `scm-spo`，而 `销售预测管理 > 销售订单` 是新版 `spo/apsSaleOrder`）。
- **解法**：在步骤 1 创建数据范围表时，核对适用对象下拉项（如 `APS销售订单`）；在角色管理功能树中，必须准确展开对应的一级目录（`销售预测管理`），保证绑定的 `buttonCode`（如 `aps:apsSaleOrder:pageQuery`）与测试账号访问的模块路由完全一致。
